ねこ博士
第2部のまとめだ。ブラウザに https://www.example.com/index.html と入れて Enter を押す。何が起きるか、ここまでの道具で順番に言えるかな。
うさ美
スマホは DHCP で住所をもらっている。まず DNS で www.example.com の IP アドレスを調べる。違うネットワークなので、ゲートウェイの MAC を ARP で調べて、ルーターに渡す。そして TCP で 443 番と握手する……。そこから先、ページをもらう話し方はまだ知りません。
ねこ博士
よくつながったね。その先の「ページをください」「どうぞ」の話し方の決まりが HTTP（HyperText Transfer Protocol）だ。ブラウザがリクエスト（お願い）を送り、サーバーがレスポンス（返事）を返す。
GET /index.html HTTP/1.1      ← 何をしたいか（GET＝ください）と、どのページか
Host: www.example.com         ← どのサイトか（1台に何サイトも同居できる）
Accept-Language: ja           ← 日本語がいい、などの希望
HTTP/1.1 200 OK               ← 状態コード 200＝成功
Content-Type: text/html       ← 中身の種類
（ここから HTML の本文）
 状態コード：200 成功／301 引っ越した（別の URL へ）／404 見つからない／500 サーバー側のエラー
うさ美
ページの中の画像は、HTML と一緒に届くんですか？
ねこ博士
別々だ。HTML の中に書かれた画像やデザイン（CSS）、プログラム（JavaScript）も、それぞれリクエストする。1つのページで何十個になることも多い。そこで HTTP も進化してきた。HTTP/1.1（1997年）は、1本の TCP の上で、1つ頼んで1つ返事をもらう、のくり返しが基本だった。前の返事が遅いと、後ろが全部待たされる。
HTTP/1.1：1本の接続で順番にやり取り。前が詰まると後ろも待つ HTTP/2（2015年）：1本の TCP の中で、たくさんのやり取りを同時に流す HTTP/3（2022年）：TCP の代わりに、UDP の上に作った QUIC を使う。パケットが1つ消えても、関係ないやり取りは止まらない。暗号（TLS）も最初から組み込み
うさ美
HTTP/2 でも、下の TCP でパケットが1つ消えたら、再送を待つあいだ、同じ接続の全部のやり取りが止まりますよね。TCP は順番どおりにしか渡さないから。
ねこ博士
その通り。それが HTTP/3 で UDP の上に QUIC という新しい決まりを作った理由だ。QUIC は、やり取りごとに別々に順番を管理するので、1つが消えても、ほかは止まらない。いまでは、大きなサイトの多くが HTTP/3 にも対応している。それから、いまの Web はほとんどが http ではなく https、つまり暗号つきだ。次のステージから第3部、その暗号の話に入ろう。

確認クイズ

Q1. Web ページを表示するとき、ブラウザが最初にすることは？（キャッシュに何も無い場合）

正解！ 相手の IP アドレスが分からなければ、握手もリクエストもできない。名前 → IP → 握手 → リクエストの順。

Q2. HTTP の状態コード 404 の意味は？

正解！ 200 成功、301 引っ越し、404 見つからない、500 サーバー側のエラー。

Q3. HTTP/3 が TCP ではなく UDP の上の QUIC を使う理由は？

正解！ TCP は順番どおりにしか渡さない。QUIC は再送などを自分で受け持ち、関係ないやり取りを止めない。
