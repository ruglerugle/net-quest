STAGE 15

層で切り分ける

障害調査と全体の地図
🎯 ミッション
ここまでの道具を層に並べ、障害を下の層から切り分ける方法を説明できるようになろう。3つの故障の原因を検査で突き止め、確認クイズに全問正解すれば合格。
未達成
ねこ博士
最後のステージだ。STAGE1 で、ネットワークの仕事を層に分けると話したね。ここまでの道具を、層の地図に並べてみよう。
アプリケーション：HTTP・DNS・DHCP・TLS（の上の HTTPS） トランスポート：TCP・UDP（ポート番号） ネットワーク（インターネット）：IPv4・IPv6・ルーター・NAT リンク（データリンク＋物理）：MAC アドレス・スイッチ・ARP・VLAN・ケーブル・Wi-Fi これがインターネットで実際に使われている TCP/IP の4層の分け方
うさ美
STAGE1 では5つに分けていましたが、こちらは4つなんですね。
ねこ博士
分け方は1つではないんだ。教科書でよく見るのは OSI 参照モデルという7層の分け方で、1980年代に国際的な標準として決められた。物理・データリンク・ネットワーク・トランスポートは同じで、その上を「セッション」「プレゼンテーション」「アプリケーション」の3つに分けている。ただ、実際のインターネットでは、その3つは1つのアプリの中でまとめて扱われることが多く、この旅でも別々には扱っていない。OSI は「どの層の話か」を言うための共通の言葉として、いまも広く使われているよ。
うさ美
TLS はどの層ですか？ 暗号にするのは、HTTP より下の仕事のような気もします。
ねこ博士
いい質問だね。TLS は TCP の上、HTTP の下に入る。だから、どちらの層とも言い切りにくく、「トランスポートとアプリケーションの間」と説明されることが多い。層の分け方は、きっちりした決まりというより、考えるための地図なんだ。
ねこ博士
この地図が一番役に立つのは、つながらないときだ。「Web ページが開けない」の原因は、ケーブルかもしれないし、DNS かもしれないし、相手のサーバーかもしれない。当てずっぽうに調べるのではなく、下の層から順に確かめる。
① リンク・ネットワーク：線や Wi-Fi はつながっているか。IP アドレスをもらえているか（169.254.x.x は DHCP の失敗、STAGE6） ② ネットワーク：ゲートウェイや相手の IP アドレスに ping が届くか ③ アプリケーション：名前が引けるか（DNS）。サーバーが返事をするか
うさ美
名前で開けないのに IP アドレスあてなら届くなら、壊れているのは DNS。下の層が全部正常で相手にだけ届かないなら、相手の側。下から確かめると、原因の場所が自然に絞れていきますね。
ねこ博士
そう。最後に、少しだけ歴史を振り返っておこう。1969年、アメリカの4つの大学をつないだ ARPANET が、インターネットの始まりとされている。1974年にサーフとカーンが TCP/IP の考え方を発表し、1983年に ARPANET が TCP/IP に切り替わった。1991年にティム・バーナーズ＝リーが Web を公開し、そこから世界中に広がった。どの時代も、新しい問題（住所不足、盗み見、速さ）が出るたびに、層のどこかを取り替えたり足したりしながら、全体を止めずに育ってきたんだ。
うさ美
層に分けてあったから、全体を止めずに一部だけ取り替えられた。STAGE1 で聞いた「層に分ける良さ」が、こういうことだったんですね。

確認クイズ

Q1. Web ページが開けないとき、下の層から確かめる理由は？

正解！ ケーブルが抜けていれば DNS も HTTP も動かない。下から正常を確かめていけば、最初に異常が出た層が原因の候補になる。

Q2. 名前（example.com）では開けないが、IP アドレスあての ping は届く。原因として一番疑わしいのは？

正解！ IP アドレスで届くなら、下の層は動いている。名前で失敗するなら、名前の解決（DNS）を疑う。

Q3. OSI 参照モデル（7層）について正しいのは？

正解！ OSI は1980年代の国際標準。セッション・プレゼンテーションの層は、実際にはアプリの中でまとめて扱われることが多い。
